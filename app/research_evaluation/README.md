# Custom memory evaluation preparation

This is a custom, unscored, no-provider development integration. It is not an
official LongMemEval-V2 score or a claim of SE6 superiority.

`scope_proof.py` executed one synthetic text insertion and a distinct cold query
for each arm. The actual SE6 SQLite Entity path was used. Linux user, mount and
network namespaces, a chroot, read-only source mounts, dropped capabilities,
locked privilege bits and a seccomp filter kept evaluator files and host drives
outside the child. `os_probe.py` checked these kernel properties before the
lighter Python audit. No game, benchmark, model or World consequence was run.

`reader_input_proof.py` consumed those existing cold results without repeating
them and prepared the exact same-model reader payload around each returned
context. No answering model consumed that payload; no answer or judgment exists.

The conventional control uses complete source-chunk BM25, short verbatim notes
and chronological neighbours. It keeps ordinary persistent memory and receives
the same raw admitted text and context/storage allowances. Indexing, cold-query
CPU, latency, RSS and storage are reported separately. The source format is
shared without importing the SE6 runtime into the conventional process.

`official_scoring.py` is trusted-evaluator-only. It loads hash-pinned official
stdlib scoring code, reuses deterministic checks and exact original model-judge
prompts, and never invokes the official retrying provider client. Prompt/parser
tests do not validate the proposed custom Nemotron judge.

`paid_runner.py prepare` writes a source-bound proposal, not an approval.
`preflight` exits blocked before credentials or network. There is no paid
transport entrypoint while the actual external-input contract is unresolved.
No old pilot gateway or permission is reused. Only after source-preserving data
capacity, defensible modality eligibility and independent history groups are
resolved can a new-purpose execution gateway and exact owner admission be bound.

Current data blockers are concrete: the first bounded official record is over
the adapter's input cap and contains screenshots in all 101 states; text-only
sufficiency has not been established. Small-tier histories form two shared
domain components, so a disjoint web/enterprise split yields one evaluation
history unit, not twelve independent environments. Current question candidates
are prospective and blocked, not a pristine frozen held-out evaluation.
